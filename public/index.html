The scanner finds names whose volatility has compressed — coiled springs that tend to release with an outsized move. The options layer then reads what the market charges for that move, and that is what decides which side of the trade you want to be on:

Every ≈13-month spread the chains support — the same names, held for a year instead of a fortnight. Out here time decay barely works for you and the level of implied volatility does most of the moving, so none of these are income trades: they are directional positions with a defined cost. Click any row for the full legs, the management rules and the caveats for that name.

Long-dated options are listed on January cycles, so the expiry nearest 13 months out can sit anywhere from ~9 to ~18 months away. The real days-to-expiry is in every row.

The ranked table behind the cards. Score is how coiled the chart is; Premium is how rich the options are. High score with a low premium score is the cleanest buy-premium setup; high score with a high premium score is the cleanest sell-premium setup. Click any header to sort.

How the pipeline works

Backend — data only

Each weekday after the US close a GitHub Action fetches the ETF holdings that define the universe, re-screens them on industry plus debt and cash ratios, downloads daily prices, recomputes the indicators without look-ahead, reads the option chains for the top-ranked names — the front month and a ≈13-month expiry — runs both strategy engines, and writes JSON:

  • data/scan.json — signals, IV read, recommendations, and this copy
  • data/charts.json — downsampled price history
  • data/backtest.json · data/calibration.json
  • data/signals.csv — the flat table, for spreadsheets

Python renders no HTML at all. Deciding what to trade got complicated enough that it needed to be data, not markup.

Frontend — this page

Hand-written, checked into public/, no build step and no external assets. It fetches the JSON above and renders it. Nothing regenerates it, so you can restyle the dashboard without touching the scanner — and read the same data from anything else that speaks JSON.

Run it locally with python run.py then python -m http.server --directory public 8765. Opening the file over file:// will not work: the browser blocks fetch there.
